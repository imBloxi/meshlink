# Home Wi-Fi (LAN) transport

Status: approved in chat 2026-10-25, approach 1 (new Link kind).

## Goal

People in the same house, on the same router, message each other with MeshLink apps and no boards. DMs, rooms, announces and safety numbers are unchanged. Only the transport is new.

## Scope

In: desktop (Electron) app, one subnet, opt-in, off by default.

Out: Android, a node that bridges ESP-NOW and the LAN, using the LAN next to a USB or Wi-Fi node, multicast, more than one subnet, the internet.

## Design

`LanLink` is a new `Link` kind (`"lan"`) beside USB, Wi-Fi and Simulator. It emulates a node the way `SimLink` does (`info`, `recv`, `sent` events), so `Messenger`, the crypto and storage do not change.

| Unit | File | Job |
|---|---|---|
| `lanframe` | `core/lanframe.ts` | Build, parse and verify an air frame with the 8-byte network tag. Pure. |
| `LanFilter` | `core/lanpeer.ts` | Duplicate filter (last 512 msgIds), per-origin rate limit, own-echo drop. Pure. |
| `LanNode` | `core/lannode.ts` | Node emulation over an injected `LanTransport`. Beacons, `info`, `recv`, `sent`. Pure, testable. |
| `lan.ts` | `main/lan.ts` | UDP socket on port 4211, interface scan, IPC. |
| `LanLink` | `renderer/lib/links.ts` | Thin `Link` adapter: `LanNode` over an IPC transport (`lanOpen`, `lanSend`, `lanClose`, `onLanDatagram`, `onLanClosed`). `LinkHandlers` gained an optional `onNotice` for the no-peers warning. |
| UI | `ConnectDialog.tsx` | "Home Wi-Fi" tile with a first-use explainer. |

### Wire format

One UDP datagram carries one air frame, exactly as in PROTOCOL.md section 1: `header 17 + body <=225 + tag 8`.

- Tag: `BLAKE2s(key = netKey, outlen = 8)` over the frame without the tag, with `ttl` set to 0. The output length is part of the BLAKE2s parameter block, so this is not a truncated 32-byte digest. The golden vector in the tests was generated by compiling the firmware's own `BLAKE2s` (`firmware/lib/mlcrypto`).
- The sender writes `ttl = 0`. The tag excludes TTL, so a future bridge can set its own.
- No relaying. One broadcast reaches the whole LAN.
- Network: the active network (`settings.activeNetId`). The open network has an all-zero key; content stays end-to-end encrypted.
- Send target: the directed broadcast address of each private IPv4 interface, never `255.255.255.255` (wrong adapter on Windows with VPN, WSL or Hyper-V). Adapters whose names look like a VPN, TAP/TUN, WireGuard, Tailscale, ZeroTier, Hyper-V/WSL/vEthernet, Docker, VMware, VirtualBox or Bluetooth are skipped, because a corporate VPN often has a 10.x address and would otherwise see MeshLink presence. This was added during implementation.
- Receive: only sources on the subnet of a real private adapter (the same list used to send), not another private subnet and not a VPN or virtual adapter.
- Receive order, as on a node: size, magic, version, zero `msgId`, `netId` (foreign is dropped; apps never relay), tag (dropped before any state changes), then own-echo, the duplicate check and the per-origin rate limit. On a private network (non-zero netKey), a forged frame cannot fill the duplicate set or use up an origin's rate budget; on the open network (all-zero key) anyone can forge such frames.
- Per-origin rate limit: the firmware's token bucket (`originAllowed`): 10 frames/s with a burst of two seconds (20 frames), on a monotonic clock. A message of more than about 20 chunks (3.4 KB) is also dropped by nodes on the radio.
- One copy of MeshLink per PC: the socket does not set `reuseAddr`, so a second copy fails with a clear port message instead of splitting datagrams.

### Behaviour

- Experimental: hidden behind the `experimentalLan` setting (off by default; Settings → Network → Experimental). Turning it off disconnects a live LAN link.
- Opt-in: nothing is sent or bound until the user connects. Startup auto-connect never picks `lan`.
- `chipId` is random per session, so the air header alone does not link a PC across restarts. Announces (outside stealth mode) expose the stable public keys and display name, and the sender's IP address is visible on the LAN, so the PC is still linkable.
- `BEACON` every 10 s, none in stealth mode.
- First-use text: everyone on this Wi-Fi can see that MeshLink runs, how often you send and your announced name (stealth hides announces); messages stay encrypted. Shown once (`lanIntro` setting).

### Errors

- No private interface: "Connect to your home Wi-Fi or Ethernet first."
- Bind fails (port in use, firewall): plain message. The first run triggers the Windows Firewall prompt; Private networks must be allowed.
- No peers after 20 s: notice about guest Wi-Fi, AP/client isolation and the "Public" network profile.
- Interfaces rescanned every 30 s. When none are left the link closes with a reason.

## Tests

- `lanframe`: firmware golden vector, tamper, short, wrong version, wrong `netId`, wrong key.
- `LanFilter`: duplicates, rate limit, own echo, bounded memory.
- `LanNode`: two nodes over an in-memory hub running a real `Messenger` DM with ACK, plus a room message.
- `main/lan.ts`: real `dgram` on loopback with injectable broadcast targets (runs on Linux CI).
- Manual two-PC checklist on Windows in `docs/lan.md`.
