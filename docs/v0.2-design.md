# MeshLink v0.2 design

Status: proposed. v0.1 (Python app + firmware v1) stays working until v0.2 reaches parity.

## Goals
1. Modern, polished desktop app with many settings (Electron).
2. One-click firmware flasher that also configures the node.
3. Separate meshes ("networks"), plus optional Wi-Fi bridging to a home network.
4. Direct messages, public rooms and private rooms.
5. Stay small, decentralized and serverless: no node or app is special.

## Stack
| Part | Choice | Why |
|------|--------|-----|
| Shell | Electron + electron-builder (NSIS installer) | Node is available; no Rust toolchain needed. |
| UI | React + TypeScript + Vite + Tailwind CSS + Radix UI primitives | Fast to build a polished, themeable UI. |
| Serial | Web Serial API in the renderer (Electron `select-serial-port` handler) | Same port object works for chat link and flasher. |
| Flasher | `esptool-js` (Espressif, supports ESP8266) | No Python or esptool.exe to bundle. |
| Crypto | `libsodium-wrappers-sumo` | Same primitives as PyNaCl, so v1 test vectors still apply. |
| Key storage | Electron `safeStorage` (Windows DPAPI) | Private key encrypted with the Windows account. |
| Data | SQLite (`better-sqlite3`) in the main process | Message history, rooms, contacts, settings. |

Repo layout:
```
firmware/            ESP8266 node, protocol v2
desktop/             Electron app
  src/main/          Electron main: window, storage, safeStorage, serial port picker
  src/core/          Protocol, framing, crypto, rooms, messenger (pure TS, unit tested)
  src/renderer/      React UI
app/                 v0.1 Python app (kept as reference and test-vector generator)
docs/
```

## Protocol v2 changes
Full spec goes in PROTOCOL.md when implemented. Summary:

- **Network id.** Air header gains `netId(4) = BLAKE2b(networkKey)[0:4]`. Nodes only relay and deliver frames with their own `netId`. Two meshes on the same channel do not mix.
- **One identity key.** Ed25519 signing key. The X25519 key for DMs is derived from it (`crypto_sign_ed25519_*_to_curve25519`). ANNOUNCE becomes signed.
- **ROOM frame (`0x04`).** `roomId(8) nonce(24) secretbox(kind, ts, senderFp(8), text, sig(64))`. `roomId = BLAKE2b(roomKey)[0:8]`. The signature stops room members from faking each other's messages. About 110 text bytes per frame. Longer text is split.
  - **Public room:** `roomKey = BLAKE2b("meshlink/public/" + name)`. Anyone who knows the name can read. It hides content from casual radio listeners only.
  - **Private room:** `roomKey` = 32 random bytes. Shared as an invite code (`mlr1:` + base32 of name + key) or a QR code. Only holders can read.
- **Node config host frames.** `CONFIG_GET (0x12)`, `CONFIG_SET (0x13)`, `CONFIG (0x24)`. Fields: node name, network name, netId, channel, TTL, beacon interval, Wi-Fi mode (off / AP / STA), Wi-Fi SSID and password. Stored in LittleFS on the node.

## Networks and Wi-Fi
- **Mesh network** = name + channel + network key. Create one in the app, then share it as an invite code or QR, like a private room.
- **Wi-Fi mode AP:** the node also runs a password-protected access point and a WebSocket server. Laptops and (later) phones can connect without USB.
- **Wi-Fi mode STA:** the node joins your home Wi-Fi and is reachable at `meshlink-<name>.local` (mDNS). The app can connect over the LAN.
  - Constraint: ESP-NOW uses the router's channel in STA mode. Every node in that mesh must use the same channel, so the app sets the mesh channel to match the router.
- The app's link layer supports USB serial and WebSocket, with the same host frames over both.

## Flasher wizard
1. The app detects a new USB serial device with a known ESP USB bridge (CH340, CP210x, FTDI) and offers setup.
2. `esptool-js` identifies the chip and flashes the bundled `firmware.bin`. GitHub Actions builds the firmware with PlatformIO, and the app release embeds it.
3. The app sends `CONFIG_SET` with the chosen network, node name and Wi-Fi mode, then reads it back to verify.
4. The node appears in the network view.

## App screens
- **Onboarding:** display name, identity key creation, optional app lock password.
- **Sidebar:** DMs, rooms, networks, nodes.
- **Chat:** message bubbles, delivery state, verified-key badge, chunked long messages.
- **Network view:** nodes seen through beacons, hop counts, last seen.
- **Flasher wizard.**
- **Settings:**
  - Appearance: theme (light/dark/system), accent color, font size, compact mode.
  - Identity: key and QR, verify contacts, encrypted backup and restore.
  - Network: active mesh, channel, TTL, announce interval.
  - Privacy: stealth mode (no ANNOUNCE), hide name, auto-delete after N days, app lock.
  - Notifications, devices, advanced (raw frame log, protocol debug).

## Honest limits
- Radio transmissions are visible. Encryption hides content, not the fact that someone is transmitting.
- Public rooms are not secret.
- ESP8266 has about 80 KB of RAM. The node stays a dumb, fast relay, and all crypto lives in the app.
